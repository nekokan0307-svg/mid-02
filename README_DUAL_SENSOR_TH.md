# FITBEAT V3 — กล้อง + เซนเซอร์โทรศัพท์ (ต้นแบบทดลอง)

## วิธีใช้
1. เปิดเกมบนโน้ตบุ๊กผ่านเว็บไซต์ HTTPS ที่โฮสต์ไฟล์ทั้งโฟลเดอร์ (หรือ localhost เพื่อทดลองกล้องโน้ตบุ๊ก) และเชื่อมอินเทอร์เน็ต
2. เลือกโหมดเกม กดเปิดกล้อง แล้วกด **สร้างรหัสเชื่อมต่อ** ในกรอบ Dual Sensor
3. เปิด **controller.html จาก HTTPS** บนโทรศัพท์ (ใช้ URL ที่แสดงบนคอมพิวเตอร์ได้หากเป็นเว็บไซต์ HTTPS ที่โทรศัพท์เข้าถึงได้)
4. กรอกรหัส Pair Code จากหน้าจอโน้ตบุ๊ก กดเชื่อมต่อ แล้วกดเปิดเซนเซอร์และอนุญาตสิทธิ์
5. เลือก LEFT ARM หรือ RIGHT ARM บนโน้ตบุ๊กให้ตรงกับแขนที่ถือโทรศัพท์ และถือโทรศัพท์ให้มั่นคง
6. ทดสอบหมัด UP / SIDE / FORWARD / DOWN โดยกล้องตรวจท่าทางและเซนเซอร์ช่วยยืนยันว่ามีการออกหมัดจริง

## ข้อจำกัดสำคัญ
- ระบบเชื่อมต่อใช้ PeerJS ผ่าน CDN และ public signaling server; ต้องมีอินเทอร์เน็ตทั้งสองอุปกรณ์ และบางเครือข่ายอาจบล็อก WebRTC
- ถ้าเปิดเกมจาก localhost บนโน้ตบุ๊ก **โทรศัพท์จะเปิด localhost ของโน้ตบุ๊กไม่ได้** และ HTTP ผ่าน LAN ไม่ใช่ secure context สำหรับเซนเซอร์มือถือ ต้องใช้ HTTPS ที่ทั้งสองเครื่องเปิดได้
- **ไม่ต้องแก้ GitHub** แต่ต้องมีวิธีให้ทั้งสองเครื่องเข้าถึงไฟล์เกมผ่าน HTTPS เช่นโฮสต์ทดสอบที่รองรับ HTTPS
- โทรศัพท์หนึ่งเครื่องช่วยยืนยันการออกหมัดของแขนที่ถือเท่านั้น อีกแขนยังใช้กล้องอย่างเดียว
- ในโหมด Dual Sensor แขนที่ถือโทรศัพท์ต้องมีทั้งสัญญาณออกหมัดจาก accelerometer และท่าจากกล้องภายใน 420 ms; ท่าอื่นใช้กล้องตามเดิม
- การเคลื่อนไหวที่มีแรงกระแทกไม่ใช่หลักฐานว่าท่าถูกต้อง; กล้องยังตรวจท่าเสมอ
- ยังไม่ได้ทดสอบกล้องจริง โทรศัพท์จริง หรือ latency ผ่านเครือข่าย; อาจต้องปรับ threshold 3.1 m/s² และ timing 420 ms
- ไม่ส่งวิดีโอจากกล้องผ่านเครือข่าย; ส่งเฉพาะค่าการเคลื่อนไหวและสถานะเชื่อมต่อผ่าน WebRTC data channel
- ถ้า PeerJS ใช้ไม่ได้ ให้เอาเครื่องหมายถูกออกจาก 'ใช้แรงเหวี่ยงช่วยยืนยันหมัด' เพื่อกลับไปใช้กล้องอย่างเดียว
